# n8n Workflows

Four importable workflows live in [`n8n/workflows/`](../n8n/workflows). They are generated by `scripts/build_n8n_workflows.py`; edit that script, not the JSON by hand.

| File | Workflow | Trigger | What it does |
|---|---|---|---|
| `01_incoming_message.json` | **WA 1 - Incoming WhatsApp Message** | Webhook `GET/POST /webhook/whatsapp` | Meta verification → validate signature & payload, identify customer, save message (backend) → answer Meta → AI agent → send reply → call WA 2 / WA 3 |
| `02_hot_lead_notification.json` | **WA 2 - Hot Lead Notification** | Called by WA 1 | Lead summary → (not notified yet?) → Gmail or log → mark notified |
| `03_human_handoff.json` | **WA 3 - Human Handoff** | Called by WA 1 + every 30 min | Assign least-busy agent → notify. While a human handles the chat, new customer messages are forwarded to them. Every 30 min the AI is resumed **only** on idle chats nobody replied to |
| `04_follow_up_automation.json` | **WA 4 - Follow-up Automation** | Every hour | Plan follow-ups (eligibility + consent + 24h/template rules) → send only **human-approved** tasks → result recorded |
| `05_error_handler.json` | **WA 5 - Error Handler & Recovery** | Error Trigger + every 5 min | Report failures → backend classifies → safe auto-retries, alerts, approvals (see [ERROR_RECOVERY.md](ERROR_RECOVERY.md)) |
| `09_error_drill_demo.json` | **WA 9 - Error Drill (demo)** | `POST /webhook/error-drill` | Fails on purpose to demonstrate the error chain |

**Design rule:** n8n orchestrates (triggers, order, retries, notifications), and the backend holds every business rule. Every backend endpoint n8n calls is **idempotent**, so n8n's *Retry On Fail* can never send a WhatsApp message or email twice.

```
Meta ──► n8n WA 1 ──► backend /webhooks/whatsapp   (signature, validation, dedupe, save)
             │ ◄── 200 to Meta right away
             ├──► backend /agent/process          (AI decides; reply saved as "pending")
             ├──► backend /internal/messages/{id}/send   (WhatsApp Cloud API, safe retries)
             ├──► WA 2 (hot lead)  ──► Gmail / log
             └──► WA 3 (handoff)   ──► assign agent ──► Gmail / log
WA 4 (hourly) ──► plan ──► approved & due ──► send each (rules re-checked)
```

## 1. Start everything (development)
The project uses its **own** n8n instance (port 5690, data in `<project>\.n8n`), so a personal n8n on 5678 is not touched.

```powershell
docker compose up -d                 # PostgreSQL
.\scripts\start-backend.ps1          # terminal 1: API on :8000
.\scripts\import-n8n.ps1             # once (n8n must be STOPPED): credential + 4 workflows, published
.\scripts\start-n8n.ps1              # terminal 2: n8n on http://127.0.0.1:5690
```
On first start, n8n asks you to create an owner account (local only). Open the editor to see the workflows and their **Executions** tab.

`import-n8n.ps1` creates the credential **"WA Agent Backend (internal key)"** (header `X-Internal-Api-Key`) from `BACKEND_INTERNAL_API_KEY` in `.env`. The key is encrypted by n8n with `N8N_ENCRYPTION_KEY`, and the temporary file is deleted.

## 2. Test without a phone
```powershell
$env:WA_APP_SECRET = "<same value as the backend's WA_APP_SECRET, if set>"
.\scripts\send-test-webhook.ps1 -Url http://127.0.0.1:5690/webhook/whatsapp -Text "What are your business hours?"
```
Then open n8n → **Executions** to see each step.

## 3. Turn on Gmail notifications (free, optional)
By default notifications use the **`log`** channel: they are written to the backend audit log, so everything works without email.

To send real emails:
1. https://console.cloud.google.com → create a project → **APIs & Services → Library → Gmail API → Enable**.
2. **OAuth consent screen** → External → add **your Gmail address as a test user**.
3. **Credentials → Create credentials → OAuth client ID → Web application**. Authorized redirect URI: `http://localhost:5690/rest/oauth2-credential/callback`
4. In n8n: **Credentials → New → Gmail OAuth2 API**, paste the Client ID and Secret, then **Sign in with Google**.
5. In **WA 2** and **WA 3**: open the **Settings** node, set `notify_channel` = `gmail`, select your credential in **Send Gmail**, then **Publish**.

Recipients come from `.env`: `SALES_NOTIFY_EMAIL` (hot leads), the assigned agent's email (handoffs), or `ADMIN_ALERT_EMAIL` if nobody is assigned.

## 4. Connect Meta (real WhatsApp)
Point Meta's webhook at **n8n** (not the backend):
```powershell
cloudflared tunnel --url http://127.0.0.1:5690                     # gives https://<random>.trycloudflare.com
.\scripts\start-n8n.ps1 -WebhookUrl https://<random>.trycloudflare.com
```
Callback URL in Meta: `https://<random>.trycloudflare.com/webhook/whatsapp`, with the same verify token as before. See [WHATSAPP_SETUP.md](WHATSAPP_SETUP.md).

## 5. Follow-up approval
WA 4 creates follow-ups with status `pending_approval`. A team member approves them (`POST /api/v1/follow-ups/{id}/approve`, or the dashboard in Stage 8), and the next hourly run sends them. Before sending, the backend re-checks consent (STOP), lead status, human mode, whether the customer already replied, and the 24h/template rule.

The default template is `hello_world` (Meta's test template). For production, create and approve your own template in WhatsApp Manager and set `follow_up_rules.template_name`.

## Troubleshooting
| Problem | Fix |
|---|---|
| `Task Broker's port … already in use` | Another n8n uses that port. The project uses 5691 for the broker (`scripts/n8n-env.ps1`); `n8n execute` from the CLI needs yet another port (`$env:N8N_RUNNERS_BROKER_PORT="5692"`) |
| Changes after import don't apply | Import/publish only while n8n is **stopped**, then start it again |
| Backend calls return 401 | `BACKEND_INTERNAL_API_KEY` changed: re-run `import-n8n.ps1` |
| Verification returns empty | Make sure you imported the latest JSON (the Respond node uses `$json.data` for text) |
